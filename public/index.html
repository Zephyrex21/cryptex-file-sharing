Our main focus

How the encryption
actually works.

No marketing claim here — this is the literal data flow. Toggle "End-to-end encrypt" on any upload and this is what happens, entirely inside your browser.

1

Encrypt in your browser

The Web Crypto API generates a random AES-256-GCM key and encrypts your file — content, filename, and file type — before a single byte leaves your device.

2

Upload ciphertext only

What reaches our server is opaque ciphertext with a generic type. There's no plaintext left to inspect — even our own upload validation is skipped for this reason.

3

Key travels in the link, not the request

Your share link looks like …?token=xxxx#key=yyyy. Browsers never send the # fragment in an HTTP request — so the key reaches whoever you send the link to, and nowhere else.

This server is structurally unable to decrypt your files

Not "won't" — can't. The key never appears in any request, log, or database row we control. The honest trade-off: if you lose the link, the file is gone for good. There's no reset button, because there's nothing on our end left to reset.
