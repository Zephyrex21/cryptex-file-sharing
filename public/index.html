Encrypt in your browser

The Web Crypto API generates a random AES-256-GCM key and encrypts your file — content, filename, and file type — before a single byte leaves your device.

Upload ciphertext only

What reaches our server is opaque ciphertext with a generic type. There's no plaintext left to inspect — even our own upload validation is skipped for this reason.

Key travels in the link, not the request

Your share link looks like …?token=xxxx#key=yyyy. Browsers never send the # fragment in an HTTP request — so the key reaches whoever you send the link to, and nowhere else.

This server only ever stores ciphertext — and never receives your key

The key lives in the link's # fragment, which browsers never send in a request, so it can't show up in a request, log, or database row. Two honest caveats: if you lose the link, the file is gone for good (there's nothing on our end to reset) — and, as with every browser-based encryption tool, your browser runs the page's code from this server, so you're trusting whoever operates it not to ship tampered code. The project is open source; for maximum assurance, read it or host your own copy.

Frequently Asked Questions
Is Cryptex really zero-knowledge?

For anything you choose to encrypt, yes in the sense that matters day to day: content, filename, and file type are locked with AES-256-GCM entirely in your browser before upload, and the key only ever exists in your share link's fragment, which is never sent to our server. The usual caveat for web apps applies — your browser runs this site's JavaScript, so you're trusting the operator not to serve modified code. The source is public, and you can host your own copy.

What happens if I lose my share link?

For encrypted files, the file is permanently unrecoverable — that's the honest trade-off of zero-knowledge encryption. There's no reset path, because there's nothing on our end capable of reconstructing the key.

Do I need an account to use it?

No. Uploading, sharing, and accessing files is entirely anonymous and token-based — no sign-up, no login, for you or whoever you share with.

What's the maximum file size?

50MB per file, whether encrypted or not. Encrypted uploads can be any file type — since the server never inspects the content, there's no type allowlist to satisfy.

Is my activity tracked or sold?

No accounts means no profile to build. There's no analytics tracking, no ads, and nothing here is sold to anyone.

Can I revoke access to a shared file?

Yes — regenerate its token any time to instantly invalidate the old one, set an expiry so it lapses automatically, or delete the file outright.
